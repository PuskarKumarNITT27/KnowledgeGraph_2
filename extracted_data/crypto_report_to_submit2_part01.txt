INTRODUCTION Insurance fraud is among the most financially damaging challenges facing the global insurance industry. Fraudulent claims inflate operational costs, raise premiums for honest policyholders, and undermine the trust that the insurance ecosystem depends upon. This project designs and implements an end-to-end fraud detection pipeline that combines two supervised classification algorithms — Decision Tree and Random Forest — with AES-256 encryption to protect sensitive claim data. The system is trained and evaluated on a real-world dataset of 1,000 auto insurance claims sourced from Kaggle. The core contribution of this work is the demonstration that strong fraud detection performance (Random Forest ROC-AUC = 0.9661) and production-grade cryptographic data protection (AES-256 CBC, overhead ratio = 1.006×) can be integrated into a single, reproducible, and computationally efficient pipeline. OBJECTIVES – Perform systematic preprocessing and feature engineering on real insurance claims data. – Address class imbalance using a manually implemented SMOTE algorithm (k = 5 nearest neighbours). – Train and compare Decision Tree (max_depth = 8) and Random Forest (n_estimators = 200) classifiers. – Encrypt every transaction record using AES-256 in CBC mode with PKCS7 padding. – Evaluate model performance using Accuracy, Precision, Recall, F1 Score, and ROC-AUC. – Benchmark AES encryption and decryption latency to confirm production feasibility. – Verify data integrity by asserting that decrypted output exactly matches original plaintext. METRICS EXPLAINED 6.1 Precision, Recall, and F1 Score In fraud detection the cost of a missed fraud (False Negative) typically far exceeds the cost of a false alarm (False Positive). The F1 Score balances both: Metric Formula Interpretation Precision TP / (TP + FP) Of all predicted frauds, what fraction are truly fraudulent? Recall TP / (TP + FN) Of all actual frauds, what fraction did the model detect? F1 Score 2 × (Precision × Recall) / (Precision + Recall) Harmonic mean — penalises extreme imbalance between the two. 6.2 ROC-AUC The Area Under the ROC Curve measures the probability that the model ranks a randomly chosen fraudulent claim higher than a randomly chosen legitimate one — a threshold-independent summary of discriminative ability: AUC Value Interpretation 1.00 Perfect classifier 0.97 Excellent (Random Forest in this project: 0.9661) 0.88 Good (Decision Tree in this project: 0.8772) 0.50 No better than random guessing Insurance Fraud Detection — NIT Tiruchirappalli Cryptography Project · 2025–26 — 11 — 7. ADVANTAGES AND LIMITATIONS 9.1 Advantages – Trained on real insurance claims data, ensuring results reflect genuine distributional patterns. – Class imbalance handled via custom SMOTE — no external library dependency required. – Random Forest achieves ROC-AUC of 0.9661, reliable across all operating thresholds. – AES-256 encryption operates at negligible overhead (1.006×), compatible with real-time pipelines. – Fully reproducible pipeline with deterministic random seeds throughout. – Feature engineering demonstrably improves performance as confirmed by importance ranking. 9.2 Limitations – Dataset is relatively small (1,000 records); generalisation to larger portfolios requires retraining. – Manual SMOTE is not vectorised and would need optimisation for datasets beyond ~100,000 records. – A fresh encryption key per record is used; production deployment requires a formal key management infrastructure. – Hyperparameters were set heuristically; systematic grid search could yield further ROC-AUC improvement. – Only binary classification is performed; multi-class fraud type detection would add investigative value. CONCLUSION This project demonstrates that effective insurance fraud detection and robust cryptographic data protection can be seamlessly integrated into a single, production-grade machine learning pipeline. The Random Forest classifier achieves an ROC-AUC of 0.9661 and an F1 Score of 0.8874 on a real claims dataset, substantially outperforming the Decision Tree baseline on the metric most meaningful for imbalanced fraud detection. The combination of systematic preprocessing, domain-driven feature engineering, and SMOTE-based class balancing was essential in reaching this performance level. The AES-256 CBC encryption layer secures every transaction record with verified integrity at a negligible overhead of 1.006×, confirming that cryptographic protection imposes no meaningful cost on real-time claim processing.
